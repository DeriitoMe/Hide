# Hide 鼠标皮肤兼容性与动态切换优化计划书

日期：2026-10-03（Asia/Shanghai）
基线：GitHub 首个公开版本 v1.0.0-beta.1
阶段：原始设计与实施记录，执行状态见第 11 节。
目标版本建议：v1.0.0-beta.2；发布范围以最终通过的兼容性矩阵为准。

## 1. 用户需求与完成目标

Hide 应始终作用于用户当前正在使用的标准系统指针。用户在 Windows 鼠标属性中应用另一套皮肤后，Hide 自动检定并改为处理新皮肤；输入时淡化／隐藏新皮肤，恢复时显示新皮肤。支持原有 50%、75%、90% 透明和完全隐藏设置，保留动画、尺寸、颜色及点击热点，并保持低常驻开销。

需要覆盖正常选择、文本选择、链接、等待、调整大小等指针角色。用户可能只改其中几个角色，也可能使用混合皮肤，不能要求所有角色来自同一个目录或同一个品牌。

目标支持面是可识别、可转换的 Windows 标准 .cur／.ani 及系统默认指针。第三方软件自绘角色、游戏内部绘制光标和特殊反色行为应列出实际支持情况。不能凭有限样本宣称所有皮肤已经支持。

## 2. 当前问题：已确认的事实与尚需追踪的部分

### 2.1 现场只读检查

用户确认通过 Windows 鼠标属性选择另一方案并点击“应用”。现场结果：

| 检查项 | 结果 |
| --- | --- |
| 当前方案标签 | Default |
| 保存的 Default 方案 | 17 个路径，指向另一套 Default 文件 |
| 保存方案与 Ikaros 原文件的内容比较 | 17 个均不同，源文件均存在 |
| 当前生效配置的 17 个角色路径／文件 | 全部仍匹配 Ikaros |
| 正在运行的产品文件 | D:\CodexProjects\Hide\Hide.exe |
| 产品文件 SHA256 | D429210546C09968EA7B620EE2E7BAE0D9FDA947B7B4BBC77C0390AC2A0024D9 |

因此确有“用户已选的新方案”与“当前指针配置”不一致，不能归因于用户只预览了皮肤。

### 2.2 现有工作方式与缺陷

src/main.cpp 中的 FILES 表和 resources/fade*、resources/hidden 固定对应 Ikaros。启动时只捕获一次 original，并用资源文件哈希确认 Ikaros。输入触发后，fade() 临时把各角色路径设为固定透明资源，通过 SPI_SETCURSORS 重载，再写回启动时捕获的路径。

因此当前机制是装载预先生成的指针资源，不是给当前屏幕上任意鼠标对象直接设置透明度。当前配置仍为 Ikaros 时，下一次输入会再次走这条固定资源加载路径。

缺少运行时方案变化监测、源文件变化监测、透明缓存失效、重新检定与新旧方案版本隔离。original 未包含方案标签／来源等用于识别切换的上下文，不能完整表示用户当前选择。

现有 fade() 有角色路径变化检查，正常情况下发现不同路径应暂停；restore_owned() 也尝试只撤销资源目录下的路径。单看这些代码，不能断言任意一次正常换方案都一定被覆盖。究竟是切换中哪一笔临时写入、恢复或全局重载造成这次配置回退，还需记录应用新方案前后的完整时序。这是实施阶段第一项任务。

### 2.3 格式覆盖只读检查

对本机 C:\Windows\Cursors 下 223 个 .cur／.ani 文件，调用现有离线转换器生成内存副本并再解析：

| 结果 | 文件数 |
| --- | ---: |
| .cur 转换／再解析通过 | 128 |
| .ani 转换／再解析通过 | 38 |
| .cur 被拒绝：含反色／XOR 像素 | 57 |

这表明当前转换器有进一步通用化的基础，也存在真实的格式限制。166 个离线成功样本不等于当前 Hide 已支持它们，不等于动画、颜色、DPI、跨应用和恢复均已实测。现有转换器还拒绝 PNG 图像项、部分 DIB 头及压缩形式；本次目录样本没有覆盖所有这些情况。

## 3. 技术判断与方案取舍

Windows 将普通箭头、文本选择等定义为标准指针角色，允许用户替换各角色图像，也允许应用使用自己的自定义指针。标准 API 支持取得当前指针、替换系统角色和构造带逐像素 alpha 的指针；没有可作为本项目通用解法的“给任意当前系统指针设置 75% 透明”的简单统一属性。

推荐继续使用原生 Win32，建立跟随当前方案的资源与状态管理。以系统角色为处理对象，动态读取用户当前指针来源并生成私有透明副本。标准指针方案是首要覆盖范围，避免为每个品牌编写专门逻辑。

| 方向 | 选择与理由 |
| --- | --- |
| 当前方案动态转换 | 主方案。较低常驻开销，透明副本与用户当前皮肤相匹配 |
| 标准角色在内存中替换 | 优先验证，可减少临时注册表写入带来的竞态与外部设置窗口读到副本的风险 |
| 文件重载方式 | ANI 保真等需求确有必要时保留备选，必须经过变更／恢复竞态测试 |
| 自绘透明悬浮鼠标 | 暂不作为主方案；需另处理原鼠标隐藏、位置／动画同步、DPI、闪烁及性能 |
| 仅用 ShowCursor 或 SetCursor | 不作为跨应用统一解法；ShowCursor 维护线程显示计数，SetCursor 的作用受鼠标输入所属线程约束 |

SetSystemCursor 能替换指定标准角色，但会接管并销毁传入对象，句柄来源及所有权需要正确处理。是否能保留各种 ANI 的完整动画、尺寸和所有目标角色，必须通过原型验证后决定，不能直接认定有效。若替代方法只剩一帧，不接受为保留动画的方案。

## 4. 建议架构

### 4.1 获取当前方案与一致性检查

建立 CurrentSchemeSnapshot，保存角色到源文件／系统默认来源的映射、注册表原始类型和值、方案标签／来源、源文件指纹、必要尺寸与颜色设置，以及递增 generation。

- 角色路径与文件内容是主要来源，方案名称用于辅助识别；不能仅凭名为 Default 或 Ikaros 判定。
- 保存的 Schemes 预设用于交叉检查，不能覆盖用户在该预设基础上单独编辑的角色。
- 当前已加载的标准指针与配置明显不一致时，进入等待重新识别状态，保留用户当前外观。不能一律重载旧配置来“修复”。
- 空路径、缺失可选角色及系统默认指针是正常情况，需要按 Windows 默认来源处理；恢复记录必须区分值不存在与存在但为空。
- 使用可用的原文件保留 ANI 全部帧和时序；不能把当前显示的一帧截图当作整个动画的源素材。

### 4.2 检测用户切换与重新绑定

监测 Control Panel\Cursors 及关联方案设置的变化，结合设置变更消息；对当前使用的文件目录监测文件替换／写入／重命名。事件唤醒工作线程，适当合并连续变化，避免按毫秒轮询全部文件。

自身加载、写回或阴影调整也可能产生通知。需要按本次操作、预期临时值和最终稳定快照识别，不能把自己的透明副本当成新原皮肤，也不能在“正在内部写入”的整个期间忽略外部变化。事务结束后必须再次核对是否出现用户新选择。

默认模式为“自动跟随当前皮肤”。增加“重新识别当前皮肤”入口，适用于没有可靠通知的更换方式。

切换流程：

1. 立即使旧 generation 失效，取消旧方案待处理淡化及旧转换任务。
2. 撤销能证明确属本次 Hide 的临时修改，保留已经生效的用户新选择。
3. 读取一致的新快照，后台校验并生成当前透明度的副本。
4. 准备期间保留当前皮肤正常显示。旧缓存不得再次参与淡化。
5. 校验任务仍对应最新 generation，再绑定并恢复正常输入检测。
6. 若出现新的鼠标操作或停止输入，不因旧的待处理按键自动进入淡化。

### 4.3 原生资源转换与缓存

将离线工具中的可用解析规则移植／完善为运行时原生模块。执行已编译程序不需要 Python 或 Pillow。

- 常见 CUR／DIB、32 位 alpha、ANI、多个尺寸与 PNG 图像项分别建立验证样本。
- 正确处理 alpha 编码与颜色，75% 透明是对应当前指针效果的 25% 强度，不能用统一灰块或其他角色替代。
- ANI 保留帧数、帧序、帧间隔和热点；CUR 保留图像尺寸组与热点。
- 反色／XOR 使用专门的能力判断和渲染验证。部分黑白反色的淡化可能有专门转换办法，应另行原型验证；复杂背景相关效果不能直接按普通 RGBA 乘 alpha 后声称保真。
- 缓存按角色来源、文件内容和透明度生成。按当前模式生成，其他模式按需准备；避免同时常驻所有皮肤所有帧。
- 源文件被原地替换，即使名称与路径相同也必须失效。读取过程中发生修改时丢弃结果，不提交半完成缓存。
- 严格检查偏移、长度、帧数、尺寸、解压和总分配量；大型合法资源超过配置上限时报告限制，并保留正常指针。
- 缓存放用户本地私有目录；清理不能删除仍被当前操作或恢复记录引用的资源。

### 4.4 应用与恢复：用户新方案优先

ApplyFade 与 Restore 必须引用同一个明确的方案版本，不能永久指向第一次启动时的 original。

恢复前重新确认当前用户选择。用户在淡化期间更换方案后，鼠标恢复、空闲、退出、崩溃守护和下次启动都应保留新方案。

需要对恢复日志及守护协议进行版本化升级，记录快照、操作编号、改动字段和预期临时值。只撤销能确认归属本次操作的字段；“路径在某个目录下”不能单独充当交易所有权证明。恢复失败保留记录，不以旧方案作为默认兜底。用户主动更改阴影或其他指针设置时，也不能恢复旧偏好覆盖新选择。

若静态角色替换可以在内存中完成，优先避免临时更改用户配置。若 ANI 需要短暂配置重载，则明确缩短写入窗口，捕获外部变更，并针对“设置窗口读取临时状态”“用户选择与恢复同时发生”建立竞态测试。无法保证状态一致时停止淡化，优先保住当前方案。

## 5. 兼容性分级

| 指针来源／类型 | 目标与处理 |
| --- | --- |
| 常见彩色 .cur | 动态识别与透明转换；验证颜色、热点、多尺寸与恢复 |
| 标准 .ani | 动态识别与逐帧转换；验证实际播放和恢复 |
| 默认系统指针、空路径角色 | 用系统默认来源解析；不能按缺文件拒绝整套方案 |
| PNG 项／不同 DIB 头 | 原生解码支持，样本与边界检查通过后列入兼容 |
| 黑白反色／复杂 XOR | 单独验证；无法保真时提示半透明受限，完全隐藏作为可选能力验证；不自动把 75% 改成 100% |
| 自绘角色、游戏内部指针、特殊桌面 | 明确标准系统角色方法的覆盖边界；暂不宣称通用支持 |

每套方案可以显示“可半透明”“可隐藏”“当前类型受限”等结果。输入时不支持淡化也必须保留当前外观，绝不能回退 Ikaros 或其他旧皮肤。

建议代码组织：scheme_tracker、cursor_codec、cursor_cache、cursor_backend、recovery_controller 与现有 input_state 各自负责单一边界。现有输入策略测试保留；新增测试应验证方案生命周期、真实绘制及恢复不变量，而不是只复述函数内部实现。

## 7. 验收与性能目标

### 7.1 必须通过的行为测试

1. A → B：运行中应用 B，输入显示 B 的淡化版本，鼠标恢复显示 B；注册表、实际外观和保存方案符合用户设置。
2. 在淡化中换 B，然后鼠标操作、超时、退出、强制终止或重启：均保留 B，不回 A。
3. 快速 A → B → C：旧任务不能提交，最后仅处理 C。
4. 只修改文本选择或正常选择，以及混合目录方案：保持未改角色，并正确处理已改角色。
5. 同路径／同文件名被替换：按新内容处理；原文件始终未被工具改写。
6. 系统默认、空角色路径、可选角色缺失：正常识别与恢复；不存在值和空值保持区分。
7. 动画：检查实际播放，不只检查 RIFF 头；帧数、顺序、时序、尺寸、热点和原动画源均可追溯。
8. 原本带 alpha 的彩色指针：在黑、白和彩色背景检查渲染，防止黑边、色偏及透明像素反色。反色类型按背景混合效果单独验收，不能仅用 alpha_max 判定。
9. 识别失败、文件被删除／锁定、内容损坏或过大：保留当前方案，不装载旧缓存。
10. 暂停、重启、锁屏／休眠、升级恢复日志，以及主程序和守护异常：检查当前用户选择与句柄所有权。

### 7.2 资源指标

以下为工程目标，实施后需实测，不作为所有皮肤的预先保证：

- 典型 32／64 像素方案下，主程序与守护稳态私有内存以约 10 MiB 内为初始目标；工作集另外报告，不能混作私有占用。
- 30 秒空闲样本参考当前约单核 0.16%，并增加长时间及活动输入样本。
- 当前方案缓存就绪且焦点已识别时，首字符淡化延迟以 P95 不超过 100 ms 为目标；皮肤准备耗时单独报告，准备阶段优先保留当前正常指针。
- 1,000 次淡化／恢复及 100 次方案切换后，内核、GDI、USER 句柄不持续增长；测试热身与稳态分开统计。
- 至少 8 小时持续使用／混合活动观察内存趋势，报告采样过程与限制。
- 源文件／解码／缓存设置明确上限。缓存转换发生在方案变化或模式变化时，不放在每次按键、每次鼠标移动或逐帧轮询里。

## 8. 发布与用户体验

默认“自动跟随当前皮肤”，提供“重新识别当前皮肤”。状态提示使用用户可理解的文字，例如“正在准备当前皮肤”或“此方案的半透明暂不支持”。不把 generation、SHA256 或注册表交易细节放进日常操作菜单。

下一公开版的 ZIP 不再携带仅供实际运行使用的固定 Ikaros 透明资源。用户自己的文件保留在原处，透明副本在本地生成。若需要测试素材，单独管理并核对其使用许可，不把测试素材当作失败后的产品默认皮肤。

更新 GitHub 的支持范围和下载教程，保留直接下载链接及 SHA256 校验。先发布 beta，按实际通过的方案／格式说明，不使用“全部鼠标皮肤都支持”的未经验证表述。

## 9. 后续执行提示词

以此计划优化 Hide，使其自动跟随当前 Windows 标准指针方案，动态检定并生成对应透明资源。先复现并定位 Ikaros → Default 应用后输入回退，修正旧缓存和恢复路径的归属问题，再实现方案监测、源文件更新、原生转换、版本化恢复与守护。用户新选择在所有恢复场景中优先，失败时保留当前方案。保持动画、热点、尺寸和原文件完整，运行无需 Python／Codex，转换不进入输入钩子热路径。完成行为矩阵、资源测量、文档和便携包验证，再按实际覆盖发布 beta。不得把离线解析成功或单个样本通过等同于支持全部皮肤。
