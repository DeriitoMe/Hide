日期：2026-10-06（Asia/Shanghai）
状态：功能与故障恢复通过；8 小时观测中断，实际约 12 分钟，真实登录及锁屏／休眠结果待验证。v1.1.0 按后续要求改为新安装默认显示托盘、主动选择静默，并增加桌面入口。见 [执行验证](QUIET-VALIDATION.md)及 [v1.1.0 要求](V1.1.0-REQUEST.md)。

## 1. 目标

Hide 在用户登录 Windows 后自动生效，输入及 Backspace 删除时按所选透明度淡化，移动、点击或滚动时恢复。用户可以关闭托盘图标，通过快捷方式按需打开设置。保持当前皮肤、透明度、空闲恢复偏好，以及原有紧急恢复入口。

自动启动与持续运行需要分别验证：启动项已经登记，不能证明程序已成功启动、仍在运行或正在正确监听输入。

## 3. 已确认的代码缺口

1. **托盘添加失败仍被当作成功。** update_tray 忽略 Shell_NotifyIconW 返回值，无条件设置 tray_added=true。后续可能一直尝试修改一个不存在的图标。已有 TaskbarCreated 处理，但仍缺少首次失败重试。此问题能解释某些图标丢失情况，不能单独解释此次两个进程都不存在。
2. **开机启动状态仅核对 Run 值。** startup_enabled 没有区分已登记、Windows 启动许可、实际启动结果和运行健康。
3. **守护负责恢复，不负责重新启动。** 主程序异常结束或被判定卡死时，守护还原指针后退出；当前没有自动重启机制。
4. **启动与退出证据不足。** 多个初始化失败分支缺少统一诊断；日志使用运行时计数而非完整日期时间，正常启动、正常退出、异常退出和守护恢复无法形成完整记录。
5. **无托盘模式还没有控制入口。** 当前重复打开程序只因单实例而退出，需要改为打开已有实例的设置窗口。

上述缺口由源码确认；本次消失的具体原因仍待后续启动记录与受控复现确定。

## 4. 实现可能性

| 路线 | 是否占托盘 | 是否保留动态输入淡化 | 判断 |
| --- | --- | --- | --- |
| 当前用户会话内静默运行，设置窗口按需打开 | 可完全关闭图标 | 可以 | 推荐，复用现有输入、换肤与恢复逻辑 |
| 将皮肤制作成固定透明的 CUR／ANI | 不需要 Hide 图标或进程 | 文件自身不能判断输入并恢复 | 适合一直透明的另一种需求 |
| Windows 自带“在打字时隐藏指针” | 不需要 Hide 图标或进程 | 提供隐藏／恢复开关，不提供 75% 淡化 | 不能完整满足现有需求 |
| Windows 服务加用户会话组件 | 可以没有图标 | 仍需会话组件操作桌面 | 安装和多会话管理更复杂，当前不优先 |

根据 Windows 公开的光标机制，CUR／ANI 保存图像、热点和动画数据；根据输入状态切换外观需要运行逻辑。隐藏托盘图标不会消除进程和内存占用。把逻辑放进驱动或其他系统进程，同样需要常驻代码，并不会自动解决输入框识别和跨应用光标问题。

普通服务处于 Session 0，不能直接作为当前交互桌面上的 Hide。服务路线仍要启动用户会话组件，因此建议保持当前用户权限的原生程序，提供接近系统功能的使用体验。

## 5. 执行阶段

### 第一阶段：补齐故障证据并修复启动流程

- 使用带日期时间的有限日志，记录版本、启动方式、初始化阶段、失败原因、退出原因和恢复结果；不记录输入文字或具体按键。
- 设置日志体积上限并轮转，避免持续写入和长期增长。
- 健康状态同时检查实例是否存活、输入监听是否就绪、皮肤准备状态、暂停状态和恢复保护。历史 status.json 明确显示为过期。
- 初始化短暂失败采用有限重试；不可恢复错误先还原指针与系统偏好，再返回明确失败状态。
- 核对现有守护的卡死判定在登录负载、锁屏、休眠与恢复时是否误判。
- 修复托盘添加结果检查和有限重试。托盘创建失败不影响输入引擎继续运行。

### 第二阶段：增加可靠的登录启动渠道

- 优先评估 Windows 计划任务：当前用户登录触发，仅在该用户已有交互会话时运行，不以 SYSTEM 或非交互会话运行。
- 登录后短暂延迟启动，并通过内部状态等待必要组件就绪。
- 配置失败后最多重试 3 次，间隔 1 分钟。计划任务的失败重试不等于实时监控，须验证各种终止方式实际是否触发。
- 禁用固定运行时长上限，避免仅因进入电池供电而停掉常驻程序；每项设置均验证实际效果。
- 以一个启动渠道为主。先确认新任务登记可用，再迁移旧 Run 项；迁移失败时保留原启动渠道，避免重复登记或完全失去启动。
- 注册、取消及更新路径均可重复执行；明确反映任务是否被 Windows 或用户禁用，不自行重新开启用户关闭的启动项。
- 正常退出不被当成失败重启；取消自启动及卸载后不再次拉起。异常重试有上限，不无限循环。
- 计划任务以当前账户权限尝试登记；如受系统策略限制，明确显示失败并保留原渠道，不默认提升权限。

### 第三阶段：提供无托盘使用方式

- 增加“显示托盘图标”设置，保留用户选择。
- 无托盘运行时不显示启动气泡；确有需要处理的失败通过设置页和受控通知告知。
- 双击程序或“Hide 设置”快捷方式，打开现有实例的设置窗口；关闭设置窗口后引擎继续运行。
- 设置页提供透明度、启动渠道及状态、启用／暂停、皮肤重新识别、退出和恢复。
- 保留 Ctrl+Alt+F12 与恢复脚本，保证没有托盘时仍有恢复方式。
- 设置界面按需创建并释放，避免把常驻程序改成高内存框架应用。

### 第四阶段：回归与试用

先交付本地试用版本；实际登录测试需要安排用户方便的重启／注销时段。完成试用后，再按后续发布指令更新 GitHub。

## 6. 验收条件

1. 实际登录测试至少 10 次，覆盖重启登录、注销登录及快速启动适用场景；分别记录启动触发、进程就绪和输入效果，不以手动启动代替。
2. 测试初始化失败、主程序异常终止和守护异常。应先恢复指针及系统偏好，按有限重试策略恢复服务能力；两进程同时被终止的情况单独记录，不能承诺任何终止方式均可自动恢复。
3. 手动退出、关闭自启动和卸载后不会意外重新启动。重复启动或多渠道触发保持单实例。
4. 不显示托盘时，输入及 Backspace 删除按当前透明度工作；可以打开设置、暂停、退出和紧急恢复。
5. 锁屏／解锁、休眠／唤醒、Explorer 重启与电池切换不会导致持续失效或重复实例。
6. Ikaros、系统默认及混合方案继续跟随当前选择；整个测试前后持久鼠标偏好与角色路径保持一致。
7. 在相同皮肤和负载下比较新版与当前版本的主程序、守护合计私有内存、工作集、CPU、句柄及输入响应分位数；记录准备阶段与稳定阶段，避免拿旧空闲数据代替新版结果。
8. 新版进行至少 8 小时驻留观测，并包含实际输入和恢复循环；确认日志有界、句柄及私有内存无持续增长。最终报告列明未完成项目。
